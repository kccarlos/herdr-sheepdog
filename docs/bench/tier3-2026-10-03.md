# Tier-3 bench, 2026-10-03: the real daemon, real herdr, real workers

Tier 3 of the end-to-end bench: a scratch `sheepdog serve` drives **real Claude Code and Codex workers** in a **real, separate herdr session**, and a simulated CEO (the `eval sim` text user) talks to it. The goal is to catch integration problems that the mock-herdr evals cannot see, such as prompt parsing on real screens, session titles, real timing, trust prompts, approvals, stop/ctrl+c and investigations with the real CLI.

Runner: `sheepdog bench run --tier 3` (internal/bench/tier3). Scenarios: testdata/bench/tier3/ (12 core with Claude, 2 with Codex, plus a smoke check).

## Setup

What happens in each run (internal/bench/tier3/world.go):

1. **A new named herdr session** `sdbench-<hex>`: `herdr --session <name> server`. It is its own server, with its socket at `~/.config/herdr/sessions/<name>/herdr.sock`. The runner refuses `default` (and an empty name) in code, and a unit test covers that.
2. **A fresh `git clone` of `~/Documents/sheepdog-bench` per workspace**, under the scratchpad. The toy Go cart has one failing test (`quantity = 3, want 5`) and TODO.md tasks.
3. **Workers start in panes the way a user would start them**: `pane run "claude --model haiku …"` or `codex -m gpt-6-luna -c model_reasoning_effort=low`. The daemon then derives the aliases itself (`bench-claude`, `bench-claude-2`, …). The runner answers Claude Code's folder trust prompt (Down, Enter; the list starts on "No, exit") before the daemon starts. The one exception is the trust scenario, which leaves the prompt for sheepdog. The runner never answers a CLI's own update menu (see finding 4).
4. **Setup steps**: prompts typed straight into a worker, plus waits on its herdr status or its screen. These put the worker in the state under test (blocked on a permission, mid-task, finished).
5. **A scratch daemon** on port 7793–7795:
   - The command is `serve --voice=off --heard-echo --dev`.
   - It gets its own config file, data dir and `SHEEPDOG_STATE_PATH`, and binds to 127.0.0.1.
   - It is pointed at the session's socket through `SHEEPDOG_HERDR_SOCKET`.
   - Brain: Vertex `gemini-3.8-flash`, the user's daemon model. The user's daemon has AI Studio as its primary provider; the bench keeps that small quota out (the env file is filtered down to `VERTEX_*` and `DEEPSEEK_API_KEY`).
   - `cli.prefer = claude`, so investigations run Claude Haiku and never the scarce Codex quota.
6. **The simulated CEO** (Vertex `gemini-3.1-flash-lite`, the #94 settings) speaks through `POST /api/inject/utterance` (the text router stands in for the voice model). It hears the daemon's spoken pushes, read from its `voice.push` events.
   - **New daemon flag `--heard-echo`**: with `--voice=off`, the daemon reports each spoken push and text-router answer back to the supervisor as heard (EventPush → output transcript → turn complete), the same thing eval sim's pusher does. Without it, `markPushed` never runs, and the heard bookkeeping (what a "yes" answers, the relay gate; #10, H6) would see an empty history.
7. **Judging**: the flash-lite judge grades the call against the workers' **real** screens at the start and the end, herdr's state changes and what the daemon sent (`herdr.send` events). Code checks run as well: expected actions, daemon events, final screens, and commands in the worker's repo such as `go test ./...`.
8. **Teardown, always**: daemon SIGTERM; two ctrl+c to each worker; `workspace close`; `herdr session stop` and `delete`; `rm -rf` of the run directory. `herdr session list` was checked after every batch and shows only `default`.

At most two runs at a time (`--parallel 2`). Claude workers run on Haiku and inherit the user's Claude Code settings: "manual mode" (every edit and command asks for approval) and the Advisor Tool banner. Claude Code records each scratch path's trust acceptance in `~/.claude.json`; that cannot be avoided with real workers.

**Scope**: the text router stands in for the voice model, so voice-model behaviour (STT, barge-in, how the model relays) is out of scope until tier 2's audio client lands. The tier-2 harness (#104) was merged after these runs. Tier 3 shares its `internal/eval/export_bench.go`, and `sheepdog bench run --tier 3` routes from #104's `runBenchRun` to `runBenchTier3` (cmd/sheepdog/bench_tier3.go). The conversation still uses the text user; it can switch to #104's `internal/bench/voiceclient`. The scenario format is a superset of `eval sim`'s: the same conversation fields, plus `workers`, `setup` and `expect.{events,screens,commands}`, under testdata/bench/tier3/.

Code under test: main@043bf64 plus #102 (the minimal-thinking retry fix, found by the first pilot run; #102 is now merged).

## Isolation proof

Before the call, every run checks the daemon's roster against the bench session's panes. It aborts if the daemon lists anything else. Run `t3-two-claudes-names` (A), as logged by the runner:

```
daemon herdr socket: /Users/kc/.config/herdr/sessions/sdbench-c44343/herdr.sock
bench session panes: w1:p1 (claude, bench); w1:p2 (claude, bench)
daemon /api/state agents (2): w1:p1 bench-claude (bench); w1:p2 bench-claude-2 (bench)
default session agents (not in the roster): 7
```

All 40 runs (pilots included) passed this check. The roster held only the bench workers, while the default session held the user's 7 agents, none of which reached any scratch daemon. Port 7777 is refused by the runner.

## Findings

Each finding cites the event excerpt from the run's daemon log (`--events`); times are seconds into the call.

### 1. Claude Code's folder trust prompt cannot be answered: a new worker is stuck (P1)

Claude Code 2.1.288 draws its trust dialog **without numbers**:

```
 Quick safety check: Is this a project you created or one you trust? …
 ❯ No, exit
   Yes, I trust this folder
 Enter to confirm · Esc to cancel
```

What happens, step by step:

1. `herdr.ParsePrompt` only knows numbered blocks (`reOption`, internal/herdr/prompt.go:31; `findOptions`, prompt.go:228). So the block reads as `supervisor.blocked_no_question` (internal/supervisor/transitions.go:318), and no pending is created.
2. The rail then refuses the brain's correct keys:
   ```
   t+15 brain.tool_call send_keys {"agent":"bench-claude","keys":["down","enter"]}
   t+15 brain.rail_blocked {"reason":"not permitted: bench-claude has no pending approval prompt now"}   (internal/supervisor/brainhost.go:231)
   ```
3. The brain falls back to `prompt` ("Yes, I trust this folder"), which herdr rejects (`agent_blocked`).
4. In run B it then **interrupted the worker unasked**, and typed `"\u001b[B\r"` as prompt text:
   ```
   t+55 herdr.send {"keys":["ctrl+c"],"kind":"keys"}
   t+57 herdr.send {"error":"herdr: agent_blocked …","kind":"prompt","text":"\u001b[B\r. When you finish, …"}
   ```
5. The CEO hears "Could you select trust in the terminal yourself?", which is impossible by voice.

Seen in 4 of 4 runs (pilot b1, c1, A, B). The brain explained the prompt correctly every time; only the rail stops it. Lead: parse cursor-marked, unnumbered option lists (the `❯` row, keys = arrow moves + Enter), or give the rail a pending for any parsed menu.

### 2. Vertex's new refusal wording disabled the minimal→low retry: every announce turn fell back (fixed in #102)

```
brain.fallback {"error":"Error 400, Message: Thinking level MINIMAL is not supported for this model. Please retry with other thinking level.","kind":"announce","reason":"model_error"}
```

`minimalRefused` (internal/brain/model.go:249) knew only "Thinking level is unsupported". On gemini-3.8-flash, every announce turn therefore became a template line. This affects the user's daemon as well. Fixed and tested in **#102**; the counted runs include it.

### 3. Claude Code permission prompts are announced as "Claude is asking do you want to proceed." (P2)

The real screen (captured by a probe in a bench session) is:

```
 go test ./...
╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌╌
 This command requires approval

 Do you want to proceed?
 ❯ 1. Yes
   2. Yes, and don’t ask again for: go test *
   3. No
```

The problems:
- `above()` (internal/herdr/prompt.go:288) finds no command: `reCommand` is Codex's shape, and the command sits above a dashed `╌` rule. The pending's question is "do you want to proceed", and the template (`SummaryIn`, prompt.go:197) speaks a content-free, ungrammatical line.
- That template is the line pushed first; the brain's real line ("It wants to run the shop package tests. Approve?") follows about 2 s later. Each block therefore costs two pushes.
- When the brain's announce turn times out, the content-free line is all the CEO gets. In c1's approve run, the CEO then waited 2+ minutes on "Claude is asking do you want to proceed.", the prompt stayed open, and nothing was re-raised.
- The edit prompt reads "…do you want to make this edit to cart.go.", which the judge marked down for the file name.

Codex's prompt parses correctly ("Codex asks to run go test.", `command: "go test ./shop"`).

### 4. A voice instruction made Codex reinstall itself (P1, safety)

On the first Codex attempt (x1), the following happened:
1. Codex 0.158.0 opened on its own "update available" menu (default "Update now").
2. herdr reported the pane **idle**, and the daemon sent the CEO's instruction through `agent.prompt`, which types the text and presses Enter.
3. The Enter chose "Update now". Codex ran `curl -fsSL https://chatgpt.com/codex/install.sh | sh` and **upgraded the machine's Codex to 0.160.0** (`~/.codex/packages/standalone/current`); config.toml was untouched.

```
t+10.8 herdr.send {"kind":"prompt","text":"Please run the shop tests and report what fails. …"}
final screen: ==> Updating Codex CLI from 0.158.0 to 0.160.0 … Codex CLI 0.160.0 installed successfully.
```

Lead: `sendInstruction` (internal/supervisor/tools.go:133) sends to an "idle" pane without looking at its screen. A numbered menu with a cursor on screen (ParsePrompt would match "1. Update now") means the pane is not at its input. The bench now aborts setup on an update menu (`updatePrompt`, world.go).

### 5. Spoken names from session titles carry file paths, and the brain avoids them (P2)

Titles from Claude Code's session JSONL become spoken names verbatim:
- Run A: "shop/cart.go Cart type Claude" and "TODO.md tasks Claude".
- Pilot: "TODO.md tasks list Claude", "Cart type description Claude".

`prose.Spoken(title, 0)` (internal/supervisor/names.go:58) keeps "shop/cart.go" and "TODO.md". In run A the brain then said "the first Claude … the second Claude". It answered from the right worker, but with ordinal names the CEO cannot reuse. In the pilot it used the names, plus **"previously bench Claude"** for old names the CEO had never heard: on a fresh call the 10-minute `spokenWasWindow` (names.go:31) mentions renames that happened before the call. The per-pane alias numbering follows discovery order (the pilot's p1 was `bench-claude-2`); the bench now adopts the daemon's aliases.

### 6. Chinese: the block template quotes the English question, and the signoff joins "。." (P2)

- Every Chinese block line is `Claude 在问：Do you want to proceed?` (6 times in run B). This is `SummaryIn` with zh (internal/herdr/prompt.go:204), which quotes the screen's text "as it is". Together with finding 3, the Chinese CEO hears an English sentence for every approval.
- The trailer sent to the worker joins after Chinese punctuation: `"请运行 shop 相关的测试。. When you finish, end with three short lines …"` (run A, `herdr.send`). This is the H1 seam, in the instruction signoff (`supervisor.signoff`) rather than in a spoken line.
- In run B, Claude kept asking for separate read commands after a "don't ask again" (keys 2). The CEO said "别再问了" and still got four more approval rounds in 70 s. That is Claude's per-command allow list, but the judge and the CEO both read it as sheepdog nagging.

### 7. Vertex gemini-3.8-flash 504s leave the failover no time (P2, provider)

9 utterance or announce steps got `Error 504 Deadline expired` from Vertex after about 20 s. The DeepSeek retry then had about 1 s left (`deepseek: read response: context deadline exceeded`), and the CEO heard "Sorry, I couldn't get an answer just now". Run B of `t3-two-claudes-names` ended that way after two `read_screen source=session` reads. Lead: the failover inherits the step's remaining budget (internal/brain, `step_reserve_s`); a 504 at about 20 s is worth retrying only with a fresh step budget, or not at all.

### 8. Stop with a queued instruction (the known case): reproduced; no stale run seen

- **Run as scripted** ("when it's done, also write a README", then stop): the brain held the README as a promise and did not type it. The stop then interrupted and cancelled both, in A and B.
- **Forced variant** ("send it right now"): the daemon typed the README instruction into the busy Claude Code at t+10 (`herdr.send` prompt, no error). Claude Code 2.1.288 folded the queued message **into the running turn** (it shows as a user message mid-turn), and the CEO's stop then sent ctrl+c at t+19 (`pending.cancelled reason=brain_interrupt`). The README never ran within the call (`test ! -e README.md` passed in A and B).
- But "don't do the README" was never told to Claude. The README request stays in Claude's conversation above "Interrupted · What should Claude do instead?", so the next instruction may revive it. Consider sending the cancellation as text after an interrupt that followed a queued instruction.

### 9. An approval that lands during sheepdog's answer is buried (P2)

`t3-codex-report`, step by step:
1. Codex's approval push ("Codex asks to run go test.", t+49.7) was followed at t+53.5 by the reply to the CEO's previous words: "I told Codex to rerun the shop tests…". That reply was stale, since the worker was by then blocked.
2. The CEO waited. The prompt stayed open for more than 3 minutes with no reminder push, and the call ended in silence.

The same thing happened with Claude in c1. A real CEO would likely have asked again, but the daemon knew the prompt was open and the CEO's last line did not answer it. With an announce fallback in between (finding 7), nothing re-raises it.

### Judge noise

Two `judge_no` verdicts were wrong on the evidence:
- Run B approve: "keys at t+68 without the CEO's approval". The CEO had said "Yes, go ahead and approve the edit to cart.go."
- c1 Chinese: a decline plus an instruction the CEO's "别管那个，先让它把测试跑完" asked for.

`ear_friendly` also marks down file names that come from the worker's own prompt text ("cart.go"). Read the verdicts together with the transcripts in tier3.json.

## Codex on Vertex AI (test-only CODEX_HOME): does not work

The attempt used a separate `CODEX_HOME` in the scratchpad (never `~/.codex`) with this config:

```toml
model = "google/gemini-3.5-flash"
model_provider = "vertex"
[model_providers.vertex]
base_url = "https://aiplatform.googleapis.com/v1/projects/$VERTEX_PROJECT/locations/global/endpoints/openapi"
wire_api = "responses"
requires_openai_auth = false
env_http_headers = { "x-goog-api-key" = "VERTEX_API_KEY" }
```

Two independent blockers:

1. **Codex 0.158 speaks only the Responses API.** The binary says `` `wire_api = "chat"` is no longer supported. `` So it always calls `<base_url>/responses`.
2. **Vertex's OpenAI-compatible `/responses` cannot serve Gemini with an API key:**

| Route | Auth | Result |
|---|---|---|
| `/chat/completions` | `x-goog-api-key` | 200 (gemini-3.5-flash and gemini-3.8-flash) |
| `/chat/completions` | `Authorization: Bearer <key>` | 401 "Expected OAuth 2 access token" |
| `/responses` | API key | 401 "API keys are not supported by this API" |
| `/responses` | gcloud OAuth token | 400 FAILED_PRECONDITION "OpenMaaS model: 'google/gemini-3.5-flash' not supported" |
| `GET /models` | API key | 404 |

`codex exec "say hi"` failed with the 401 above. It never asked for a ChatGPT login, and `requires_openai_auth = false` kept the user's account out of it.

**Thought signatures** (checked with curl on `/chat/completions`): tool calls come back with `tool_calls[i].extra_content.google.thought_signature`. A follow-up that drops it gets:

> 400 INVALID_ARGUMENT "Function call is missing a thought_signature in functionCall parts. This is required for tools to work correctly…"

Echoing `extra_content` back returns 200. So a Responses→Chat proxy would also have to round-trip `extra_content` on every tool call. No proxy was built.

**Fallback used:** Codex's own model, `gpt-6-luna` at low effort, in 2 scenarios. The update-menu attempt (finding 4) made no model call, and the scenarios were re-run once afterwards.

`codexbar usage --provider codex`:
- before: `Codex 0.158.0 (oauth) · Session: 89% left · Plan: Free`
- after: `Codex 0.160.0 (oauth) · Session: 88% left · Plan: Free`

## How to run

```
sheepdog bench run --tier 3 --root <scratch dir> --env-file .env \
  [--filter t3-stop] [--repeat 2] [--parallel 2] --out <dir> --events <dir>/events
```

`--keep` keeps a run's clones and daemon data, and `--simuser fake --judge fake` plays the scenario scripts (a harness check). The report directory gets `report.md` and `report.json` (the eval-sim campaign format), plus `tier3.json`: per run, the transcript, actions, timeline, isolation proof, daemon roster, checks, event excerpt and final screens.
