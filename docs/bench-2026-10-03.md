## Decided fixes
- #9 voice session degrades: refresh the voice session (no resume) when the phone comes back after > 30 min away, or after > 2 h of continuous session, at a quiet moment; reseed with the last 12 verbatim utterances, filtering out bare "on it"/"checking" lines and self-relays.
- #10 dropped CEO instruction: mark a push as spoken when it actually starts playing, not when queued; plus a content-match safety net (a gated call whose text matches a real CEO utterance from the last 10 s is accepted and logged).
- #17 push lost when the CEO starts speaking: use the playback reports and output transcript to tell whether a push was actually heard. Needs-you items and kept promises (approvals, "tell me when…") are re-queued by the daemon after the CEO's turn; other unheard pushes are reported to the brain ("the CEO did not hear: …") so it decides whether to mention them. The same mechanism covers #18 (interrupted answers) and #19 (body skipped).
- #13/#14 length and language (CEO, 2026-10-03: static code cannot judge when more words are needed, so it should not try): the brain's prompt says spoken text is short by default, longer when the CEO asks for detail, in the language the CEO last used. The code cap becomes a single high runaway guard for every spoken line (~45 s of speech: ~110 English words or ~200 hanzi), with CJK-aware sentence/character counting so it works for Chinese; the EarBrief/EarReply split goes away. The "。." / "？?" join seam is fixed regardless. Length is watched through the scorecard, not enforced.
- #2 AskUserQuestion meta options: the daemon parser marks "Type something." and "Chat about this" as non-answer options; neither is shown on the phone card nor read as a spoken choice, and the fast "yes/no" path never maps to them (every decision can be made by voice anyway). "Type something." stays usable in the background: when the CEO's answer matches none of the options, the brain may select it and type the CEO's words through the rail. "Chat about this" is not used. Daemon-only change; no iOS release needed.
- #15 asks, repeats, stale nags: (a) prompt + evals: ask only when a decision is open, never on plain status/finish lines; (b) the daemon tells the brain the facts it cannot see — that the event was already spoken and with what words (the template line that went out while the brain was still thinking), and the pending's real state (waiting / expired / answered) — and the brain decides whether to skip, add or correct; (c) the only code guard is an anti-loop cap: a 4th spoken line about the same event within 30 s is dropped. No rule restricting which agent a push may mention (withdrawn).
- #8 pending approval TTL: the pending lives as long as the pane is still blocked at the same prompt (herdr state + screen), not 120 s; a tap on the phone card is always valid. The fast "yes" path only applies within ~1 min of the announcement; later, the CEO's words go to the brain with the facts ("<agent> asks X, waiting N min") and the brain decides, asking when unsure.
- Provenance hardening (found while reviewing the worker-output guardrail): (a) neutralise the delimiter strings inside wrapped worker text and add a per-call random nonce to BEGIN/END_WORKER_OUTPUT so a screen cannot forge the end marker (internal/brain/tools.go wrapWorker); (b) worker-derived roster fields in list_agents (task, last_result, pending question) are marked as worker data or covered by the RULES.md provenance rule.
- Agent naming (three layers): machine id (pane id, never spoken, used by code/app/API); full alias (unique, used in brain tool calls); new **spoken name** computed by the daemon as the shortest form that is unique among running agents — kind alone ("Claude"), else project + kind ("sheepdog Claude"), else the worker's own session title + kind ("README Claude") when one project has several of a kind, else project + kind + number; a name the CEO gave always wins. The daemon reads worker session titles (Claude Code writes `ai-title` entries in its session JSONL, e.g. "README"; Codex shows a thread title — storage location to confirm) into the roster as facts; the brain uses spoken names verbatim in speech, picks a word or two when a title is long, mentions the old name when a name just changed, and resolves whatever the CEO calls an agent (asks when unsure). The voice model gets the current spoken names as silent context whenever the roster changes (fixes its stale alias list) and in the STT custom vocabulary. Renaming by voice ("call that one docs") goes through a parameter on an existing brain tool, not a new tool.
