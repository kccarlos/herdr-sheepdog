# Engine v2 knowledge base: behaviours the new engine must show

This file lists every behaviour the new task engine (Go, inside the sheepdog daemon, herdr-core only) must show. It replaces the old Python engine's tests, which are not ported and will be deleted. Each row says what an observer sees, not how the old code did it, and names its evidence.

**How to read a row.** ID is a new stable id, KB-<area>-<n>. "Behaviour" is implementation-neutral; exact numbers and incident ids (FAC-, SHEP-, SDF-, WUKO-, #nnn, field note N) stay in the sentence because they are the evidence, and "(old value: N)" marks an old constant rather than a rule. Kind is PITFALL (a real failure seen in the field or in tests that this guards against) or RULE (a product or safety rule). Source lists the extraction ids (T1-, T2-, T3B-, T4B-, T5-, D1-, plus T3-/T4- from the cross-check files) and then the test function names, file:line or doc section, separated by semicolons. "Maps to" names where design.md carries the behaviour (see "How the design was checked" below). A few old status words are kept because the owner sees them: Working, Ready, Needs you ("asks" or "reply"), Done; "coordinator" means the old "Assistant"; "scheduled wake" means the old "Autopilot"; "periodic pass" means the old tick; "terminal host" means hc.

**Counts.** Rows in: 794 from the six primary extractions (T1 150, T2 120, T3B 118, T4B 136, T5 149, D1 121; by kind 413 RULE, 356 PITFALL, 25 ARTEFACT), cross-checked against the thinner kb-t3 (76 rows) and kb-t4 (55 rows), plus rules and pitfalls from four research notes (critique, adapters, merge-recovery, go-surface) and three shared case files read by the editor. Rows out: 599 main rows (298 PITFALL, 301 RULE) in 20 sections, which is above the expected 350 to 500 because merging was kept conservative; 48 lines in Appendix A (not carried over); 29 conflicts (one resolved by the editor) and 13 doubts in Appendix B. Appendix C rows start with "spot" so they are not main rows. Duplicates across inputs were merged into one row with all sources. Every primary input id appears in a main Source cell or in Appendix A, every main row has six cells, and every cited test name exists (all checked by script).

**How extraction was done.** Six agy jobs extracted the tables by line range of test_herdr_task.py (four ranges), the other test and case files, and the design docs and field notes, using claude-opus-5-5 and gemini models; ranges 3 and 4 were extracted twice (b-files primary). Four other agents wrote the research notes. This editor merged, rewrote and classified the rows, opened 40 random rows' sources plus a few targeted ones (Appendix C), and filled old constants from the code. Not every source was re-opened by a person.

**Spot check.** 40 random rows: 0 wrong (0%); 33 fully checked, 7 partly; one targeted check outside the sample found an extractor error (T4B-124, CLI order) and fixed it. The error rate is under 10%.

**Sections.** 1 Launch and permissions (LCH) · 2 Agent runs (RUN) · 3 Task lifecycle and scheduling (TSK) · 4 Review rounds and verdicts (REV) · 5 Recap, size and budget (CAP) · 6 Retro round (RET) · 7 Accept bar, PR, CI, merge, cleanup (MRG) · 8 GitHub and git pitfalls (GIT) · 9 Coordinator (COO) · 10 Asks, owner answers, proof, delegation (ASK) · 11 Quiet rule, alerts, digest (QUI) · 12 Plan, milestones, graph (PLN) · 13 Quota and pools (QTA) · 14 Settings and typed rules (SET) · 15 Worktrees, sandbox, secrets (WKT) · 16 Environment (ENV) · 17 Design loop (DSN) · 18 Project start and doctor (STA) · 19 Devices, simulators, machines, later plugin (DEV) · 20 Test hygiene (TST) · Appendix A Not carried over · Appendix B Conflicts and doubts · Appendix C Spot check.
