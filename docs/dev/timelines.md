# Timelines, collisions and invariants

Written 2026-09-25 against `main` at `0be70e6`; updated through 2026-10-03 (`043bf64`). Code-verified: every claim cites the
file that decides it. Cells marked **[V]** were read in code (and, where named, a
test); **[I]** are inferred from code paths no test or log exercises. Log facts come
from `~/.local/share/sheepdog/events/2026-09-2{3,4,5}.jsonl`, timestamps UTC as logged,
event names and counts only.

**Why this page.** The bugs of 2026-09-24/25 were not missing states inside one
component. They were collisions between timelines that each behaved correctly on
their own. The voice model's filler landed between an orchestrator tool call and its result
(#62). A orchestrator reply arrived after the page closed (#64, #65). An interrupt push came
after Gemini finished generating while the phone was still playing (#70). The phone's
speaker output came back as an utterance (#63, #65).

The stance this page follows: the harness exists to make up for what a
single-threaded model cannot see (ordering, delivery, timing, provenance). It must
not fence in the model's judgement. Not every combination deserves a code path.
Only a failure seen in a real log gets a fix; the rest become eval or audio-e2e
scenarios (docs/dev/iteration-2.md, "Rules for every change").

## 4. Arbitration: who wins

| Principle | As the code implements it | Where it deviates |
|---|---|---|
| (a) live input beats everything | A user turn goes before event turns (`queue.go` `release`); an event turn yields at a step boundary; barge-in flushes speech (C6); stop cancels the in-flight user turn and a fresh instruction (`stop.go`) | Event turns are not cancelled by stop (intended); the stop's reply never waits on them (it is code, no orchestrator turn). Barge-in does not cancel the orchestrator turn; its reply comes later or goes stale (C7, intended) |
| (b) what is owed beats unsolicited news | Owed finishes get 15 s, not 6 s; kept promises are spoken at every chattiness level; late `needs_user` lines are added; investigation answers skip the ceiling; late replies are pushed | The orchestrator's event queue is FIFO whatever is owed; the voice push queue now lets owed lines pass idle news (C29, #72). An investigation delivery yields at most twice, then becomes "ask me what it found" |
| (c) blocked > finished > idle chatter | A block speaks its code sentence at 2 s; a finish waits for the orchestrator; interrupt only for `needs_user` on a new block (`applyCeiling`) | No kind priority in the orchestrator queue or the push queue. The pending slot is last-writer-wins: the newest block, or an instruction, displaces an older question (C19). A pane's block waits behind its own finish turn (C18) |
| (d) never over the user, never to nobody, hold don't drop | `speakingUntilLocked` / `vad.Hold` gate every non-silent push; pushes held while no client (TTL 5 min + event); `hasListener` before an inline reply; an approval prompt's pending lives as long as the pane waits at it | Drops by policy, with events: `brain.push_late`, `push_stale`, `reply_stale`, coalesced. A Gemini answer on a dead generation, or cancelled after the reply came, is pushed instead (`voice.tool_result_pushed`); other tool responses on a dead generation are dropped with the `send_error` field only. Since #72 a provider switch carries the queue over, and a push after its send errors, or a kept promise on a stale block, logs `voice.push_dropped`. A spoken Gemini tool result waits while the user speaks (≤ 10 s, `voice.push_deferred {shepherd_speaking}`), as a push does; stop() never waits |
| (e) newer replaces older per agent; FIFO across agents | Orchestrator event key = alias; a newer delivery replaces an older one; utterances coalesce while queued | Unreachable for one pane's worker events (C18). Agents with no alias share the key `"an agent"` and can coalesce across panes [I]. The push queue never coalesces (#72 orders it by class; it still does not merge) |
| (f) ties by the daemon's clock, logged | Windows are clock-based (authorise 30 s, cancel 30 s, echo 2.5 s, relay 4 s, input grace 1.5 s); decisions logged: `brain.push_decision {waited_ms}`, `brain.rail_blocked {reason}`, `brain.reply_stale` | Staleness is decided by sequence counters (`inputSeq`, `acceptedSeq`, `connGen`, relay `gen`), not the clock. Order at a mutex (turn lock, `pushQ`, transcript ingestion) is arrival order and is not logged |

**The fixed mechanisms, and where each is used**

1. **Single writer with priorities** — the orchestrator `turnLock` (and `Brain.Reset` takes it as user).
2. **Coalesce** — orchestrator event key; `supervisor.coalesce` for queued utterances; `claimRunLocked` joins a run of inputs.
3. **Hold / release** — `holdPush`/`pumpPushes` (no client); interrupt → idle while speaking; `claimInput` grace; `AnnounceWait`; `ReplyWait` then detach.
4. **Yield at a step boundary** — event turns before each model call; the delivery retry.
5. **Atomic re-check at send time** — `AnswerPrompt` under `s.mu` (the rail); `pendingStillOpen`; `hasListener`; `execTool`'s `Speaking()`; `deliverLate`'s `acceptedSeq`; `relayUnanswered`'s `gen`.
6. **TTL with an event** — `pending.expired` (instructions only), `promise.expired`, `supervisor.push_loop_dropped` (30 s per event), `voice.push_dropped`, `brain.fallback timeout`, reset-confirm 20 s, `investigate_max_s`.

**Collisions handled by none of these:** C1 is fixed by render-time normalisation (`modelOrder`), not arbitration. C5 is a text-and-timing heuristic. C18 is a seventh, implicit mechanism: the per-pane mutex in `app.go`. The Gemini `sendOn` generation check re-checks and then *drops* instead of holding. C3 is a lifecycle join. C15 was plain discard; it is a carry-over since #72.
