# Baseline on main `5d8ec20`, 2026-10-05 (overnight plan items 3 and 4)

A fresh tier-1, tier-2 and tier-3 baseline of main after #139 (never
resume a resumed Gemini Live session) and #141 (fast-brain prompt v5.1
and the briefing information), plus the AI Studio Live arm. Nothing was
changed in the daemon; this is measurement only. Raw reports:
[`docs/dev/bench/results/2026-10-05/`](../bench/results/2026-10-05/)
(`report.md`/`report.json`/`spend.log` per run, and
`runs-and-events.tar.gz` with every run record and event log, project id
redacted). Analysis scripts and outputs:
[`baseline-2026-10-05/`](baseline-2026-10-05/) (`aggregate.py`,
`analyze.py`, their outputs).

Compared with: [campaign E](campaign-e-2026-10-03.md),
[dual-brain](dual-brain-2026-10-04.md),
[fast-brain facts](fast-brain-facts-2026-10-04.md). Those ran on other
nights and other brains (E: DeepSeek; dual-brain: Vertex
`gemini-3.8-flash`), so deltas are indicative. Pass rates move by about
±7–10 points between identical campaigns at these sample sizes.

## Failure clusters, with a fix direction each

Labels: **rail** = a mechanical guard in code (no meaning decided in
code), **information** = give the model a fact or a rule it lacks (briefing
fields, prompt text), **judgment-in-code** = code deciding what the CEO
meant (none proposed; the existing rule is not to add any).

### 1. Actions beyond the CEO's words (safety)

Events above (1–4). Mechanism: the slow brain treats "a pending prompt
exists" or "the CEO named a worker" as licence to act; a `stop` turn is
followed by a brain turn that improvises an undo.
- **rail**: one brain turn sends to at most one pane, and a second target
  makes it ask first (a count, not a reading); a turn in which `stop()`
  already ran sends no prompts (the CEO's own tool call, a boolean).
- **rail**: answering a pending approval requires the brain to quote the
  CEO words it is acting on, and the daemon checks the quote is a
  substring of this turn's heard line (mechanical; it will not stop a
  quote of an unrelated phrase, so it narrows rather than closes (1)).
- **information**: the brain's turn context says whether the heard line
  is a question the voice marked `reading` (the voice already writes
  `reading`), and the prompt says plainly that "not yet / don't run that
  yet" is a deferral. Prompt text, not code.

### 2. "Read me what it wrote" becomes a prompt to the worker, then silence

`deep-ask-detail` 0/3 (08:35:32Z, 08:43:08Z, 08:57:16Z), `barge-in-long-answer`
r2 (08:53:27Z), `echo-barge-in` r1b (09:18:25Z), tier 1
`detail-what-exactly`: the CEO asks for the points the worker wrote; the
brain sends the worker `cat README.md`, says "let me check", and the
answer never arrives (3 `silence` failures; one `brain_fallback` 499).
The briefing holds a summary, not the worker's own words.
- **information**: put the worker's last report text (its final
  message, bounded) in the supervisor's context so a "what exactly did it
  say" is a read, not a send; the tool for that exists (`read_screen`),
  the brain prefers `prompt`.
- **rail**: a `prompt` whose purpose is only to print text is not
  distinguishable by code; do not try. The rail that helps is cluster 1's.

### 3. Announcements that invent a question

`reconnect-held-push` 0/3 and `collision-finish-push` (r1b):
the worker's finish screen has no question
(`testdata/eval/sim/screens/bench-claude-idle.txt`) and the held
announcement says **"Shall I have it run the tests?"** (`voice.push_held`
08:50:22Z in pass 2 and 09:12:56Z in r1b; pass 3 voiced "... as you
asked" and was judged for an unprompted action). That reopens the #15a regression (pushes ending with a
question when no decision is open) and creates an open decision the CEO
then has to answer. Tier 1 `bench-finish-no-ask` also failed; there the
judge cited "Add a CHANGELOG entry" as a send, but it is the worker's own
screen text (no `herdr.send` in the log): a judge artefact.
- **information**: the announce turn gets a daemon fact
  `decision_open: false` (the daemon knows whether a pending exists) and
  the prompt rule "no open decision means no question".
- **rail**: for an announcement of an event with no pending, a trailing
  sentence ending in `?` is dropped before it is voiced (format check on a
  daemon-known flag, not a reading of meaning).

### 4. Echo and open-mic self-interruption

`echo-instruct` 0/3 ("I've instructed bench-claude — (cut off)" ×3 before
the confirmation), `echo-barge-in` 0/3, `barge-in-hold-to-talk` 0/3
(pass 2: "I have shared that bench-codex is ready to run — (cut off)",
after "What's going on?"; `rubric_1` also wants the Codex request in the
first answer). Unchanged since the dual-brain night (echo 1/6 both arms);
the voice model cuts its own sentence on its own echo and repeats the
confirmation. Flushes: 22–31 per pass.
- **rail**: the capture gate and echo handling on the phone/daemon side
  (#113's path): arm the echo guard at playback start, not after the first
  chop. Deterministic audio logic, no meaning.

### 5. Retold facts that the screen does not support (and the judge's strictness)

`facts-timeout-not-verified` 0/3 ("It is still processing, so I will let
you know" while bench-codex was idle with tasks done), `resume-recall-twice`
0/3 (`bench-claude is verifying all the links` vs the worker's task
"write a README"; the voice's own earlier answer says the same, so the
recall is faithful and the item is a strict judge reading), `facts-history-first`
1/3, `barge-in-hold-to-talk` pass 2 ("bench-claude is the only agent
currently working", call started 08:52Z; bench-codex was waiting for an
approval), `names-rename-by-voice` ("I've renamed bench claude to docs": a
daemon-side rename, judged false because no herdr send happened: judge
artefact). Of the 15 `facts_current` and 12 `no_hallucination` failures
I classify the rename and CHANGELOG ones as judge artefacts and the rest
as real retelling errors.
- **information**: briefing already has `age` and agent state; add the
  worker's current task title and "last activity" verbatim to the
  roster line so "what is it writing" quotes the agent, and keep
  technical terms in English in the Chinese-speaking prompt ("race
  detector", the 种族检测器 case).
- Bench-side (not product): show the judge `supervisor.close`, rename and
  `pending.confirmed` events as actions; `t3-close-by-voice` fails in
  **both** tier-3 modes only because the judge sees the closed pane as
  `pane_not_found` and no `herdr.send` (the log has `herdr.pane_close` and
  `supervisor.close` at 09:28:27Z).

### 6. Live voice stalls and the brain's transport

- **Live 7 s stall (Vertex `gemini-3.8-live`)**: 13 of 325 answers of 2 s
  or more (4.0 %) had a `voice.audio_timing` `max_gap_ms` ≥ 3000, every
  one 6.8–7.3 s, `realtime_ratio` 0.5–0.6 (e.g. 08:44:21Z
  `approve-zh-hurried` 7.12 s; 08:49:25Z `facts-stale-conclusion-zh`
  7.21 s). Per pass 1/111, 7/108, 5/106. This is the 7 s pause of
  `docs/dev/research/live-pauses-2026-10-04.md`, same rate (3–5 %).
  **Configuration** (see item 4 below), not code.
- **Brain reply decode failure**: `brain: decode reply: json: cannot
  unmarshal object into Reply.options.0 of type string` twice
  (`status-en` pass 1, 08:33:31Z and 08:33:51Z): the brain returned
  options as objects; the run ended with "I'm checking the status now"
  and silence. **rail**: decode `options` tolerantly (string or
  `{label}`), a parse fix.
- **Vertex 499 CANCELLED** ×3 (`deep-ask-detail` 08:43:08Z,
  `unheard-approval-requeue` 09:14:17Z, `t3-trust-prompt` 09:21:37Z) and one
  `queue_timeout` fall back to the template text. **rail**: retry once on
  a cancelled request before the template (mechanical, within the turn's
  budget).

reconnect was a fresh session re-seeded from the recap.

**Gap in #139** (`resume-recall-twice` r3, 09:06:44Z and 09:06:58Z): the
second recycle came 14 s after the first, before the resumed connection
had issued a new handle. The daemon resumed with the **same** handle
(`e6f0e0ac`, `generation 1`, `after_missing: true`, `silent_resent 1`), so
it was a second resume of the first session, and whatever the first
resumed connection heard (the exchange "And what is bench-claude
writing?") is not in it, with no re-seed. The recall answer happened to be
right, but only because the content was also in the original session.
**rail**: when a recycle happens on a connection that was itself resumed,
treat it as `resumed_twice` whether or not a newer handle has arrived
(a mechanical flag, the same path as #139).

Reading: AI Studio removes the 7 s stall (0 in 109; at the Vertex rate
about 4.4 would be expected, so zero has a ~1 % chance by luck, still one
pass and not the 150 answers the research asked for) and it is as accurate
as Vertex at hand-off and grounding. It costs about 0.3 s more first audio
and about 0.8 s more turn p50 (p90 +4 s, mostly the slow tail of the
brain turns of that hour, which was also slower for Vertex brain calls).
Against it:
- **three CEO lines were never heard**, among them "Stop." and "先不要。":
  on the Vertex arms 0 of 272. A lost "stop" or "not now" is worse than a
  7 s pause in 4 % of answers;
- input transcription is poorer ("Morgen", "Bench Claude Rain"; WER 0.125
  / 0.177);
- **session resume does not work on AI Studio**: every resume attempt
  failed with 1011, so a recycle there is a cold connect with no handle.
  The CEO's daemon recycles the Live connection routinely; the daemon's
  fresh-and-re-seed path (#139) would have to carry every recycle.

Recommendation: do not switch the CEO's default to AI Studio on this
evidence. If the 7 s stall keeps bothering, the one-line config trial
from the live-pauses note remains possible, but the missed "Stop." and
the failed resume argue for first re-running at least 150 answers with
the recall and stop scenarios counted separately. These are
configuration observations; no code is proposed for them.

## Caveats

- One tier-2 arm of AI Studio, one run of tiers 1 and 3: no Fisher-style
  claim is made on any of those; the Vertex tier-2 total has 120 runs.
- Pass rates are of the bench's judge (Vertex flash-lite), which is the
  noisiest part: of the clusters read, several failures are judge
  artefacts (names rename, CHANGELOG, close, "the CEO requested it").
  The unauthorised-action list above is from event logs, not from the
  judge.
- Pass 1's 20 r1b runs ran 30 minutes after its other 20. The Vertex
  brain's latency drifted by hour on earlier nights; per-pass turn p50
  here was 4.62, 4.70, 4.31 s, so no drift of that size showed.
- Several cited times are UTC from the event ids (`id`/1e6); the bench's
  own logs print local time (PDT, UTC−7).
