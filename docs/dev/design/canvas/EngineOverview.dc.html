Factory engine: how it works

For each task it walks one ordered table from the top and stops at the first row that fits. Nothing is remembered as a phase, so nothing can be stuck in one.

How it works

  1. 1The engine stores records of what happened: a ready report, a verdict, an accept. Each is tied to a commit. It never stores “where the task is”.
  2. 2It reads facts about the world, such as CI, mergeable, branch tips and live terminals, from GitHub, git and herdr. Facts are read again, not kept.
  3. 3For each task it walks one ordered table from the top and stops at the first row that fits. That row says what to make sure of and who the task waits on.
  4. 4“Make sure of” names a thing, such as a reviewer run for round 2 at this commit. The engine compares it with the world and does only the difference.
  5. 5Every report and command passes the acceptance table first. It refuses what is not allowed, and nothing changes.
  6. 6Every number a rule uses is a setting the owner can change. Every safety rail is code.
