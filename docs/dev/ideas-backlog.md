## Honest Answer: Should We Self-Host a Voice Runtime (`sglang-omni`)?

**No.** Keep Gemini Live and GPT-Live as the voice transport, and steal only `sglang-omni`'s systems engineering (delivery pacing, cut alignment, epoch fencing, uplink ring) and its tiny ~10 MB CPU/CoreML models (Silero VAD + Smart Turn v3.2).

1. **Wrong hardware and OS**: `sglang-omni`'s `/v1/realtime` full-duplex and omni pipelines require Linux + CUDA (Triton KV kernels, SGLang CUDA graphs, FlashInfer). Its Apple Silicon path (`sglang_omni_mlx`) is a separate single-model ASR/TTS binary, not the duplex session runtime—so it cannot run on a user's Mac alongside coding agents.
2. **Upside-down economics for bursty single-user voice**: One developer speaks ~15–60 minutes a day and sits silent while agents code. Cloud realtime APIs with Sheepdog's standby/lazy-open gate cost **~$0.50–$4/day ($15–$90/month)** with zero ops. Self-hosting Qwen3-Omni, MiniCPM-o 4.5, or Nemotron VoiceChat requires an 80–141 GB H100/H200 (**$1,440–$2,520/month** 24/7; 60–180s cold starts prevent scale-to-zero), and even a 24–48 GB GPU for a 5-process Streaming Cascade costs **$430–$860/month** (requiring **50–150+ concurrent paying daily users** on a shared pool just to break even on raw GPU rental).
3. **Brittle tool-calling fit**: Sheepdog relies on a strict thin-voice contract (never answer code questions yourself, always call `to_supervisor`, call `stop` on cancel, relay exact identifiers). In `sglang-omni`, MiniCPM-o and PersonaPlex 7B lack native duplex tool calling, Nemotron VoiceChat 11B throws a `ValueError` if you replace its hardcoded checkpoint system prompt, and small open models hallucinate tool args far more often than frontier cloud voice models. Self-hosting only makes sense for an air-gapped enterprise Linux server or a multi-tenant cloud tier with >100 simultaneous active voice streams.
