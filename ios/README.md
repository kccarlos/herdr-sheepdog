# Sheepdog for iOS

The iPhone app for [sheepdog](../README.md): the microphone, the speaker
and the screen. The daemon on your computer owns the models and the
agents. There is no sheepdog server and no account.

**Using the app** (install, the demo, pairing, notifications,
troubleshooting) is in [docs/iphone-app.md](../docs/iphone-app.md). Its
privacy policy is the daemon's [privacy page](../docs/privacy.md). This
page is about building the app.

## Build it yourself

You need a Mac with Xcode 27 (the version the project is built and tested
with; CI pins Xcode 27.1 and Xcode Cloud uses the latest release),
[XcodeGen](https://github.com/yonaskolb/XcodeGen) 2.46 or newer, and an
Apple developer account. The project has no third-party dependencies. The
Xcode project is generated by XcodeGen from `project.yml` and is not
committed.

From a checkout of the sheepdog repository:

```sh
brew install xcodegen
git clone https://github.com/kccarlos/herdr-sheepdog.git
cd herdr-sheepdog/ios
xcodegen generate
open Sheepdog.xcodeproj
```

Every command on this page runs in `ios/`.

**Signing with your own team.** In `project.yml`, set `DEVELOPMENT_TEAM` to
your Team ID. Change the bundle IDs (`bundleIdPrefix` and the
`PRODUCT_BUNDLE_IDENTIFIER` values) to IDs that you own, then run
`xcodegen generate` again. Set `SHEEPDOG_APP_GROUP` to an App Group ID of
your own as well. The app uses the Push Notifications, Time Sensitive
Notifications and App Groups capabilities, a widget extension for the Live
Activity and a Notification Service Extension that decrypts relay
notifications. Automatic signing creates what they need.

**Push notifications.** Apple delivers a push only when it is signed with
a key of the team that signed the app, so the shared relay (the daemon's
default) cannot reach a build signed by your team. Either create an APNs
auth key (`.p8`) for your team in the Apple developer portal and set it in
the daemon's `[push.apns]` ([CONFIG.md](../CONFIG.md),
[iphone-app.md](../docs/iphone-app.md#notifications)), or run your own
relay ([relay/README.md](../relay/README.md#self-hosting)). Debug builds
use the APNs sandbox and Release builds use production; the app tells the
daemon which one applies.

## Tests

```sh
xcodebuild -scheme Sheepdog -destination 'platform=iOS Simulator,name=iPhone 17 Pro' -skipPackagePluginValidation test
```

`-skipPackagePluginValidation` lets SwiftTerm's build-tool plugin run
without the "Trust & Enable" prompt Xcode shows the first time; in Xcode
itself, click Trust & Enable once instead. Most UI tests need a fixture
daemon and skip themselves when there is none
([docs/dev/status.md](docs/dev/status.md#running-the-tests));
The Kit also builds for macOS (`SheepdogKitMac`; it excludes
`SwiftTermSurface.swift`, and `AudioRoute` is filled in by the iOS app from an
`AVAudioSession.Port`); `xcodebuild -scheme SheepdogKitMac -destination
'platform=macOS' test` runs its unit tests, the platform-neutral share of
`SheepdogKitTests`.

The Mac menu-bar app (`SheepdogMac`, product `Sheepdog.app`; macOS 14 or
later) builds and tests the same way, after `xcodegen generate`:

```sh
xcodebuild -scheme SheepdogMac -destination 'platform=macOS' test
```

Debug is signed automatically with the team in `project.yml`. Without that
team's certificate, add `CODE_SIGN_IDENTITY=-` to run the tests with ad-hoc
signing. The app reads the daemon on `127.0.0.1:7777`; to point it at another
port, `defaults write com.github.kccarlos.herdr-sheepdog-mac sheepdogDaemonPort -int 7801`.
How it is built is in
[docs/dev/architecture.md](docs/dev/architecture.md#sheepdogapp-macos).
`.github/workflows/ios.yml` runs the whole suite, fixture daemons included,
on every PR that touches the app, and its smoke tests on every PR that
touches the daemon's API.
