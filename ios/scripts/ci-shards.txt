# Which iOS CI job runs which tests (.github/workflows/ios.yml, through
# scripts/ci-plan.sh). One line per entry: the job, then an xcodebuild
# -only-testing identifier (a bundle, a class or Class/testMethod).
#
# - `smoke` runs on every PR that changes the app or the daemon's API and on
#   pushes to main; the other jobs run only for app changes (the full
#   suite). docs/dev/development.md (CI/CD) has the tiers.
# - Smoke is the unit tests (with the protocol goldens) and the fixture-
#   daemon UI tests closest to the API (pairing, history, settings,
#   reconnect, questions), kept under about 10 minutes of tests; the
#   offline-demo UI tests go in the shards.
# - Every class in Tests/SheepdogUITests must be listed as a whole class in
#   exactly one job, or the plan job fails (scripts/ci-plan.sh check). A
#   method listed in smoke runs there only in the smoke tier; in the full
#   tier the job that runs its whole class covers it.
# - Each job has one simulator: IPadUITests runs on an iPad, alone in its
#   job; everything else on an iPhone. HistoryApprovalUITests (after a
#   daemon restart) and ReconnectUITests (with the restarter) get their own
#   steps.
# - Shards are balanced by the median of recent CI durations (seconds, in
#   the comments); put a new class in the shortest shard.
