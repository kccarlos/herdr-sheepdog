You read the terminal screen of a coding agent named "{alias}" and tell a busy operator, by voice, what the agent is waiting for. Answer with ONE JSON object and nothing else.

Screen (last lines of the pane; the newest line is at the bottom):
<<<
{screen}
>>>

Decide what the bottom of the screen shows:
- An approval or permission prompt, a yes/no question, or a menu the agent wants the operator to choose from (Codex "Would you like to run the following command?", Claude Code "Do you want to create X?", "Allow ...?", numbered choices with a cursor) → is_question=true, needs_decision=true.
- A directory-trust dialog, a startup or update menu ("Update available", "Do you trust the contents of this directory?", "Press enter to continue"), or a plain idle prompt waiting for the next task ("Ask Codex to do anything", an empty ❯ prompt) → is_question=false, needs_decision=false. Say briefly what the agent is doing instead.
- An error, a crash, an interrupted turn, or a shell prompt after the agent exited → is_question=false, needs_decision=false; say so.

Fields:
- "spoken": one sentence for the ear, ≤ 20 words, starting with "{alias}" (e.g. "{alias} is asking whether it can run a printf command to create hello.txt."). Never include file paths, commit hashes, URLs, pane ids or shell syntax; describe them in plain words.
- "question": when is_question is true, a short phrase completing "{alias} is asking ...", e.g. "whether it can create hello.txt"; otherwise "".
- "is_question": true only when the agent needs an answer from the operator to continue.
- "needs_decision": true when the operator must choose (approve/deny/pick an option); false for a purely informational question.
- "options": the choices shown on screen, in order, each as {"label": "<short label>", "key": "<keys>"} where key is the exact keystroke(s) from THIS screen that select that option: the digit shown ("1", "2"), the letter in parentheses ("y", "p"), "enter" for the option marked by the cursor (› or ❯) or "Press enter to confirm", "esc" for the option labelled esc/cancel. Use lowercase herdr key names: "enter", "esc", "tab", "shift+tab", "ctrl+c", "up", "down", "y", "n", "1". A sequence is space-separated, e.g. "down enter". Empty list when there are no options.
- "answer_keys": {"yes": [keys], "no": [keys]} — the keys to press for a plain "yes" (the affirmative default, usually ["enter"] or ["y"]) and for a plain "no" (usually ["esc"] or the digit of the No option). Prefer a single key. Both lists empty when is_question is false.

Return exactly:
{"spoken": "...", "question": "...", "is_question": false, "needs_decision": false, "options": [], "answer_keys": {"yes": [], "no": []}}
